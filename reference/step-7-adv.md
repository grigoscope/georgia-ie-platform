# Этап 7. Celery, Telegram-бот и уведомления

## Критерии достижения

1. Настроены Celery, Redis и Celery Beat.
2. Периоды создаются автоматически.
3. Напоминания создаются по расписанию.
4. Бот доставляет уведомления.
5. Дубликаты исключены.
6. Временные ошибки повторяются ограниченно.
7. PDF отправляется через бота.

## Фоновые задачи

### Курсы

- загрузить курс;
- повторить временную ошибку;
- не перезаписать ручной курс;
- сохранить источник.

### Налоговые периоды

- создать период;
- пересчитать;
- обновить просрочки;
- пересчитать накопительный итог.

### Уведомления

- первое напоминание;
- повторы;
- дедлайн;
- просрочка;
- Telegram;
- email;
- повтор доставки.

### Инвойсы

- создать PDF;
- отправить PDF;
- удалить истёкшую ссылку;
- пометить просроченные инвойсы.

### Экспорт

- создать XLSX;
- уведомить о готовности;
- удалить временный файл.

## Расписание

Ежедневная задача проверяет дату в `Asia/Tbilisi`.

События:

- 1;
- 4;
- 7;
- 10;
- 13;
- 15 число;
- просрочка после 15.

Сообщение создаётся только при выполнении условия.

## Дедупликация

Пример ключа:

```text
tax:{user_id}:{year}:{month}:{event}:{channel}
```

События:

- first_reminder;
- repeat_4;
- repeat_7;
- repeat_10;
- repeat_13;
- deadline;
- overdue.

Повторный запуск не создаёт дубль.

## Проверка перед отправкой

- пользователь активен;
- канал включён;
- Telegram связан;
- декларация не подана;
- налог не оплачен;
- доставка ещё не выполнена;
- период актуален.

Текст строится перед отправкой.

## Telegram-бот

Команды:

- `/start`;
- `/app`;
- `/help`;
- `/settings`.

### Привязка

1. Пользователь запрашивает одноразовый код.
2. Открывает бота.
3. Бот принимает код.
4. Backend проверяет срок и одноразовость.
5. TelegramConnection связывается с User.

### Webhook

- HTTPS;
- secret token;
- быстрый ответ;
- длительные действия в Celery.

### PDF

- проверить владельца;
- получить файл;
- отправить документ;
- сохранить message ID;
- записать результат;
- не дублировать.

## Повторные попытки

- только для временных ошибок;
- экспоненциальная задержка;
- ограничение числа попыток;
- постоянная ошибка сохраняется;
- администратор видит причину.

## Тесты

- даты 1, 4, 7, 10, 13, 15;
- часовая зона;
- нулевой период;
- декларация подана;
- налог оплачен;
- выполнено одно действие;
- Telegram отключён;
- Telegram недоступен;
- повторный запуск;
- просрочка;
- PDF;
- истёкший код;
- поддельный initData;
- повтор кода.

## Проверка этапа

С помощью тестового времени воспроизвести месяц и убедиться, что после выполнения действий уведомления прекращаются, а повторный запуск не создаёт дублей.
