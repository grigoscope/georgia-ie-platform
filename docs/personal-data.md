# Персональные данные

## Какие данные обрабатываются

Система может хранить:

- email пользователя;
- пароль в виде криптографического хэша;
- данные профиля индивидуального предпринимателя;
- идентификационные и контактные данные;
- данные финансовых счетов и платёжных методов;
- сведения о доходах;
- данные контрагентов;
- данные инвойсов;
- Telegram user ID и chat ID;
- настройки уведомлений;
- загруженные пользователем файлы;
- журнал административного аудита.

## Цель обработки

Данные используются для:

- авторизации пользователя;
- ведения журнала доходов;
- подготовки налоговых расчётов;
- создания инвойсов;
- формирования отчётов;
- доставки уведомлений;
- работы Telegram Mini App и Telegram-бота;
- обеспечения безопасности и аудита административных действий.

## Доступ

Пользователь имеет доступ только к собственным данным.

Административный доступ ограничивается Django Admin и правами сотрудников.

Опасные административные действия должны фиксироваться в журнале аудита.

## Срок хранения

В учебной версии проекта автоматическая политика удаления по сроку хранения не реализована.

Для production необходимо определить сроки хранения:

- пользовательского профиля;
- финансовых операций;
- инвойсов;
- файлов;
- уведомлений;
- audit log;
- резервных копий.

## Удаление аккаунта

Перед коммерческим использованием необходимо определить процедуру удаления аккаунта.

Она должна учитывать:

- пользовательские данные;
- финансовые записи;
- инвойсы;
- загруженные файлы;
- Telegram-привязку;
- уведомления;
- требования к сохранению audit log.

## Audit log

Audit log предназначен для контроля административных действий.

При удалении пользовательских данных необходимо отдельно определить, какие данные аудита должны сохраняться для безопасности и расследования действий администратора.

## Экспорт данных

Пользователь может получать часть своих финансовых данных через функции экспорта журнала.

Для production рекомендуется определить процедуру полного пользовательского экспорта.

## Backup

Персональные данные также могут присутствовать в резервных копиях PostgreSQL.

Доступ к резервным копиям должен быть ограничен и защищён.

## Ограничение

Проект является учебной системой и не является готовой юридической политикой конфиденциальности.

Перед коммерческим использованием необходимо привести обработку персональных данных в соответствие с применимым законодательством и фактической инфраструктурой сервиса.
